Colour

Fifteen tokens, each with a light and dark value. Semantic names only — no raw hex in component code, which is what lets the dark theme swap cleanly.

--{{ t.name }} {{ t.light }} {{ t.dark }} {{ t.note }}

Two rules earn their own tokens. Text on a brand fill always uses --onBrand — white in light, dark ink in dark, because the lighter salmon cannot carry white type at 4.5:1. Destructive UI always uses --danger, never a hardcoded red, for the same reason.

Typography

Source Serif 4 for headlines, prices and key figures. Figtree for everything else — UI, body, labels, chips. Both from Google Fonts.

Listings have no photography yet, so every image position ships as a labelled slot on --slot with a 115° stripe. The caption names the shot required. Layouts already reserve the correct aspect ratio, so photos drop in without a relayout.

Ground rules

  1. Mobile first. Every screen reflows to a single column with no horizontal scroll; nothing uses a fixed width.
  2. No tap target below 44px.
  3. Body text holds 4.5:1 against its background in both themes; headline-scale type holds 3:1.
  4. Figures are tabular and right-comparable; price and EMD always appear as a labelled pair.
  5. Information architecture, filters, form fields and copy are unchanged from the current product — this is a visual layer only.
